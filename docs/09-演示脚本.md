# 09 · 验收演示脚本（8 分钟）

> PPT 要求：验收演示 8 分钟 + 问答 5 分钟；按真实用户路径走一遍，不念 PPT；至少两人讲解；准备断网兜底。

## 1. 演示前 5 分钟检查

```bash
# 确保数据干净、服务可用（先停掉已启动的服务，避免数据库文件被占用）
npm run db:reset
npm run mock -- --clear --days 30 --sessions 1800 --seed 42
npm run report
npm start
```

- 打开 <http://127.0.0.1:3000/admin/>，用 `superadmin / Admin@123456` 登录一次，确认看板有数据。
- 另开一个终端，准备一条 C 端 mock 登录 + 报名命令，防止小程序现场网络问题。
- 准备断网兜底：`reports/screenshots/` 的截图、`reports/analytics_summary.md`、本文档。
- 确认 `.env` 中 `WECHAT_MOCK=true`；如果现场要演示大模型，提前配置 Key 并生成一次，避免现场等待 30 秒。

## 3. 逐段脚本

### 0:00—0:50 开场

> “我们做的是 XX 摩托销售管理系统的 C 端小程序 + 运营后台。四个人分工：我负责登录、用户、活动、报名和用户行为分析；前端同学负责首页、车型、活动页面；另一位后端同学负责车型、内容、收藏和智能客服；组长负责仓库、联调和答辩。
>
> 我这部分解决三个问题：**谁能进来**（登录 / 手机号 / 角色）、**活动怎么发和怎么报**（发布 / 防重 / 名额）、**运营怎么判断效果**（模拟数据 / 热度 / 趋势 / 漏斗 / AI 解读）。”

### 0:50—2:10 登录、手机号、用户禁用

操作：

1. 打开小程序「我的」→ 未登录 → 点击登录。
2. 展示 `wx.login` → 后端换 openid → token 存本地。
3. 点击报名 → 提示先授权手机号 → `getPhoneNumber` → 绑定成功。
4. 切到后台「用户管理」，搜索该用户，展示手机号 / 状态 / 报名数。
5. 点击「禁用」，填写原因；回到小程序刷新 → 提示账号被禁用。

讲解要点：

- “token 是无状态的，但用户状态每次请求都查库，所以禁用立即生效，不用等 token 过期。”
- “手机号有部分唯一索引，一个手机号只能绑一个微信账号；未授权手机号的用户不能报名，但可以正常浏览。”
- “后台有两种角色：超级管理员能管账号；运营管理员只能管活动、用户和分析。直接调账号接口会 403。”

如果现场不方便开小程序，用 curl：

```bash
curl -X POST http://127.0.0.1:3000/api/auth/wechat/login \
  -H "Content-Type: application/json" \
  -d '{"code":"mock:demo-user-1","phoneCode":"mock:13800138000"}'
```

### 2:10—4:10 活动发布与报名

操作：

1. 后台「活动管理」→「+ 发布活动」。
2. 填标题、时间、名额 3（故意小一点，方便演示满员）、状态「立即发布」。
3. 保存后，C 端活动列表出现。
4. 用 3 个不同 mock 用户报名；第 4 个用户报名 → 提示「名额已满」。
5. 用第 1 个用户再次报名 → 提示「你已经报名过该活动」，并显示已有报名编号。
6. 演示取消报名 → 名额释放 → 第 4 个用户可以报名。

讲解要点：

- “防重不是只靠前端按钮置灰：数据库有部分唯一索引 `(activity_id, user_id) WHERE status='confirmed'`，服务端事务里还会先查一次。”
- “名额校验在 `BEGIN IMMEDIATE` 事务里做 `COUNT + INSERT`，并发 10 个请求抢 1 个名额，测试验证只有 1 个成功。”
- “未开始、已结束、已下架、未授权手机号，分别返回 1002/1005/1010，前端文案可以分开提示。”
- “编辑活动带 version 乐观锁，两个人同时改不会互相覆盖。”

### 4:10—5:20 统计与导出

操作：

1. 活动行点击「统计」。
2. 展示已报名 / 剩余 / 报名率 / 取消 / 近 14 天每日报名 / 最近报名。
3. 点击「导出完整名单 CSV」，用 Excel 打开，展示中文正常、列齐全。
4. 回到后台「用户管理」，展示某个用户的报名记录。

讲解要点：

- “CSV 带 UTF-8 BOM，Excel 直接打开不乱码；以 `= + - @` 开头的内容会加单引号，防止公式注入。”
- “导出会写审计日志，谁在什么时候导出了哪个活动，都能查。”
- “统计只算 confirmed，取消会释放名额，但取消记录保留，方便算取消率。”

### 5:20—7:00 模拟数据与分析

操作：

1. 切到「数据看板」。
2. 展示 KPI：PV / UV / 报名 / 转化率 + 环比。
3. 展示模块热度：首页 / 车型 / 活动三足鼎立。
4. 展示趋势：周末高、11-16 有活动脉冲。
5. 展示漏斗：五步、每步会话数、流失率、最大流失环节。
6. 切 7 天 / 30 天，展示区间切换。

讲解要点：

- “数据不是随手编的：固定 seed，30 天、约 1800 个会话、约 6000 条事件、约 130 条报名；同一 seed 任何人都能复现。”
- “漏斗不是各步骤独立去重，而是同一 session 内严格按时间顺序：先首页、再活动列表、再详情、再点击、再成功。这样‘先看详情后看列表’的乱序访问不会污染漏斗。”
- “最大流失在详情 → 点击报名，说明不是没人来，而是来了不点；这比‘活动没人看’更具体。”
- “模块热度按 PV，UV 按登录用户 / 匿名设备去重；口径都写在报告里。”

### 7:00—7:50 大模型解读

操作：

1. 点击「生成解读」。
2. 如果有 Key：展示「大模型生成」标签、模型名、4 条发现、4 条建议。
3. 如果没 Key：展示「规则兜底」，说明原因。

讲解要点：

- “Prompt 要求模型只输出固定 JSON：headline、summary、findings、recommendations、risks、confidence；所有数字必须来自输入数据。”
- “输出会做结构校验；无 Key、超时、非 JSON、结构不合格，都会自动规则兜底，并在页面和数据库里标注 `source=fallback`，不会把兜底伪装成大模型。”
- “只发聚合指标，不发手机号、昵称；结果落库，保存输入快照，答辩时能解释结论基于哪份数据。”
- “模拟数据置信度是 medium，报告里明确写了数据局限。”

### 7:50—8:00 收尾

> “这部分完成了登录、用户、活动、报名、统计、导出、分析、AI 解读的完整闭环；接口契约、数据库脚本、模拟数据、测试和报告都在仓库里。已知局限是 SQLite 单机、漏斗按 session、未做后台登录限流；如果继续做，会接真实埋点、加 MySQL、补活动维度漏斗和登录限流。”

## 4. 问答准备

| 可能问题 | 回答要点 |
| --- | --- |
| 为什么用 SQLite？ | 课程演示零依赖、单文件可复现；表结构 / 索引 / 事务都按关系库设计，换 MySQL 只改驱动层。 |
| 报名防重怎么做的？ | 部分唯一索引 + 事务内查重；重复提交返回 1004 和已有报名编号。 |
| 名额会不会超卖？ | `BEGIN IMMEDIATE` 事务内 COUNT + INSERT；并发测试 10 抢 1 只有 1 成功。 |
| 禁用用户后 token 还能用吗？ | 不能；每次请求查库校验 status，返回 1008。 |
| 为什么漏斗按 session？ | 匿名用户跨会话无法稳定识别；session 更接近“这次访问有没有走完”，改版评估更敏感；局限已写报告。 |
| 两个转化率为什么不一样？ | 报名/访客转化率分母是 UV；漏斗总转化率分母是进入首页的 session；报告里两个都给了。 |
| AI 会不会编数据？ | Prompt 限定只能引用输入数字；输出做结构校验；失败走规则兜底并标注 fallback。 |
| 没有 Key 怎么演示？ | 规则兜底也用真实统计数字生成解读；页面明确显示「规则兜底」，不冒充大模型。 |
| 四人怎么避免冲突？ | 按领域分目录、路由自动发现、契约先行、一人一分支、合并前互看 diff；公共文件变更先和组长说。 |
| 如果重做会改什么？ | 接真实埋点、MySQL、登录限流、活动维度漏斗、后台前端组件化。 |

## 5. 断网 / 翻车兜底

- 后端起不来：直接打开 `reports/screenshots/02-dashboard.png`、`03-activities.png`、`06-dashboard-ai.png` 讲。
- 小程序网络失败：用 curl 演示登录 / 报名，再切后台看结果。
- 大模型超时：说明会自动兜底，现场等 30 秒或直接展示已生成的 `reports/ai_insight.json`。
- 数据被改乱：`npm run db:reset && npm run mock -- --clear && npm run report`，30 秒内恢复。
- 投屏分辨率低：后台按 1440×900 设计，浏览器缩放 90% 更稳。
