## 4. 缺陷与修复记录

| 编号 | 现象 | 原因 | 修复 | 回归 |
| --- | --- | --- | --- | --- |
| BUG-01 | 管理接口返回 200 但 `data=null` | 认证中间件只校验、不调用 `next()` | `requireUser/requireAdmin/optionalUser` 改为中间件并 `return next()` | 全部管理接口恢复 |
| BUG-02 | 新建活动 500，SQLite 参数绑定失败 | 可选字段 `undefined` 不能绑定 | `readActivityInput` 统一 `?? null`，并补名额校验 | ACT-01/02 通过 |
| BUG-03 | CSV 测试读不到 BOM | `fetch().text()` 按规范会剥离 UTF-8 BOM | 测试检查原始字节 `EF BB BF`；文件本身带 BOM | AN-02 通过 |
| BUG-04 | 管理列表首屏空白 | 同 BUG-01，中间件未放行 | 同上 | 页面恢复正常 |
| BUG-05 | 模拟数据报名成功过少 | 详情随机到不在报名窗口的活动 | 生成器优先选择当前 session 可报名且未报名的活动 | 报名约 130 条 |
| BUG-06 | AI 兜底把“最近一天”与前一天比较 | 当天是进行中数据 | 改为近 7 天日均 vs 前 7 天日均 | 报告结论更稳 |
| BUG-07 | 小程序调用 `/api/auth/wx-login`、`/api/auth/phone`、`/api/signups/mine` 接不上 | 后端只提供 `/api/auth/wechat/*`、`/api/users/me/signups` | 增加三个等价别名，复用同一处理函数 | AUTH-14 通过 |
| BUG-08 | 示例配置默认监听 `0.0.0.0`，演示密钥/密码暴露到局域网 | `.env.example` 默认值不适合非本机监听 | 默认 `HOST=127.0.0.1`；非本机监听强制检查 JWT/后台密码，Mock 给警告 | SEC-01/02 通过 |
| BUG-09 | 空数据库漏斗仍报告 100% 流失 | `0/0` 被算成 0%，`100-0` 变成 100% | 无数据时 `hasData=false`，率/流失/总转化/最大流失全部 null | AN-10 通过 |
| BUG-10 | operator 通过 `/api/admin/users/:id/signups` 仍能看完整手机号 | 用户报名列表漏了脱敏 | 复用 `phoneView`，operator 统一 `139****0001` | AN-11 通过 |
| BUG-11 | D 旧分支合入 main 会删除 `miniprogram/`、`admin/` | 旧分支历史不含主线前端，合并按删除处理 | 不再合旧分支；从 `main` 新建 `feature/lumenh26-integration`，只叠加后端 | 合并前 `git diff --name-status` 检查 |
| BUG-12 | 仓库跟踪了含默认密码账号的 `server/data/app.db` | 演示库被误提交 | 移除数据库；`.gitignore` 已忽略 `server/data/`，用 `npm run db:reset` 生成 | 集成脚本不再上传 `app.db` |

## 6. 未覆盖 / 后续补测

- 真实微信 `code2Session` / `getPhoneNumber` 需要 AppID、Secret 与真机，当前仅 mock 测试。
- 大模型真实调用未在 CI 中跑（需要 Key），只测了兜底；真实调用需手工验证一次。
- 小程序页面本身不在本仓库测试范围，只提供接口契约与调用示例。
- 未做压力测试；并发用例是 10 个请求抢 1 个名额的功能级验证，不是 QPS 压测。
- 未做浏览器兼容性矩阵；后台在 Edge / Chrome 最新版手工验证。
