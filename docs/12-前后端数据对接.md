# 12 · 前后端数据对接

> 基于 `feature/lumenh26` 拉取到的 `miniprogram/`、`admin/`、`.impeccable/`、`DESIGN.md`、`PRODUCT.md`。
> 本文说明 D 的后端如何与现有前端、数据文件对接；C 的车型 / 首页 / 收藏 / 客服接口仍由 C 提供。

## 1. 结论先看

| 端 | 现状 | D 侧要做什么 |
| --- | --- | --- |
| 小程序登录 / 手机号 / 活动 / 报名 / 我的报名 | `miniprogram/api/index.js` 已按 D 的正式路径调用 | 后端已提供，另有旧路径别名兼容 |
| 小程序行为埋点 | `utils/track.js` 调用 `POST /api/track` | 本次新增 `/api/track`，写入 `visit_event` |
| 小程序首页 / 车型 / 收藏 / 客服 | 仍走 `mock/` | 不属于 D；C 提供接口后把 `USE_MOCK` 改为 `false` |
| 管理后台 | `admin/js/data.js` 是纯 mock，`app.js` 直接渲染 `DB` | D 提供接口和字段映射；B 负责把 `DB` 替换成 `fetch` |
| 数据分析 | admin `renderAnalysis()` 读 `DB.analysis` | D 的 `/api/admin/analytics/summary` 提供同样三块数据，需要 B 适配 |

## 2. 小程序联调

`miniprogram/config.js`：

```js
module.exports = {
  USE_MOCK: true,                 // 联调 D 模块时改 false
  BASE_URL: 'http://127.0.0.1:3000',
  TIMEOUT: 10000,
  SUCCESS_CODE: 0
}
```

联调步骤：

1. 后端启动：`npm run db:reset && npm run mock -- --clear --days 30 --sessions 1800 --seed 42 && npm start`。
2. 开发者工具「详情 → 本地设置」勾选「不校验合法域名」。
3. `USE_MOCK` 改 `false`，只测「活动」「我的」两个 Tab；首页 / 车型 / 客服仍会请求 C 的接口，未就绪时先保留 mock 或由 C 提供。
4. 登录 → 授权手机号 → 活动列表 → 活动详情 → 报名 → 我的报名。
5. 后台用户管理 / 活动统计可以看到刚产生的用户与报名。

> D 已返回的字段：`signedUp`、`signupCount`、`signupOpen`、`phase`、`remaining`、`mySignup`。小程序 `utils/activity.js` 直接按这些字段换算按钮，不需要额外适配。

## 3. D 接口与小程序调用对照

| 小程序 `api/index.js` | D 后端 | 说明 |
| --- | --- | --- |
| `wxLogin(code)` → `POST /api/auth/wechat/login` | 同名 | 返回 `{ token, user }`；旧路径 `/api/auth/wx-login` 也兼容 |
| `bindPhone(code)` → `POST /api/auth/wechat/phone` | 同名 | 返回 `{ user, changed }`；旧路径 `/api/auth/phone` 也兼容 |
| `getMe()` → `GET /api/users/me` | 同名 | 返回 `{ user }` |
| `getActivities(params)` → `GET /api/activities` | 同名 | 分页 `{ list, total, page, pageSize }` |
| `getActivity(id)` → `GET /api/activities/:id` | 同名 | 返回活动 + `mySignup` |
| `signup(id, {remark})` → `POST /api/activities/:id/signup` | 同名 | HTTP 201；错误码 1002/1003/1004/1005/1010 |
| `getMySignups(params)` → `GET /api/users/me/signups` | 同名 | 旧路径 `/api/signups/mine` 也兼容 |
| `track(data)` → `POST /api/track` | 本次新增 | 见下一节 |

### 3.1 埋点 `/api/track`

前端 `utils/track.js` 只传：

```js
{ event: 'view', ts: Date.now(), module: 'activity' }
```

后端映射到 `visit_event`：

| event | 前端 props | 写入 |
| --- | --- | --- |
| `view` | `module=home` | `module=home, page=home, action=view` |
| `view` | `module=bike` | `module=bike, page=bike_list` |
| `view` | `module=bike_detail, bikeId` | `module=bike, page=bike_detail, target_id=bikeId` |
| `view` | `module=activity` | `module=activity, page=activity_list` |
| `view` | `module=activity_detail, activityId` | `module=activity, page=activity_detail, target_id` |
| `view` | `module=mine` / `chat` | 对应模块与页面 |
| `signup_click` | `activityId` | `module=activity, page=activity_detail, action=signup_click` |
| `signup_success` | `activityId` | 同上，`action=signup_success` |
| `bike_sort` / `bike_price_filter` / `bike_tag_filter` | 排序 / 价格 / 标签参数 | `module=bike, page=bike_list` |

登录用户记录 `user_id`；匿名用户记录 IP + UA 的哈希。会话按“IP + UA + 当天”生成，**中途登录不会拆 session**，所以 `signup_click → signup_success` 可以进同一漏斗。

## 4. 管理后台对接

当前 `admin/js/data.js` 是演示数据，`admin/js/app.js` 直接操作 `DB`。B 接后端时按下面映射替换：

### 4.1 活动管理

`GET /api/admin/activities?page=1&pageSize=8&keyword=`

| admin 字段 | D 字段 |
| --- | --- |
| `name` | `title` |
| `signup` | `signupCount` |
| `quota` | `quota` |
| `date` | `startAt`（UTC ISO，展示前转本地） |
| `status` 进行中 / 未开始 / 已下架 / 已结束 | D `status` + `phase`：`draft` / `published` / `offline` + `upcoming` / `ongoing` / `ended` |

发布 / 下架：

```text
POST /api/admin/activities/:id/publish
POST /api/admin/activities/:id/offline
```

导出：

```text
GET /api/admin/activities/:id/signups/export
```

> `super_admin` 导出完整手机号；`operator` 导出脱敏手机号。

### 4.2 用户管理

```text
GET   /api/admin/users?page=1&pageSize=10&keyword=&status=
PATCH /api/admin/users/:id/status   { status: 'active' | 'disabled', reason? }
GET   /api/admin/admins?page=1&pageSize=10
POST  /api/admin/admins
PUT   /api/admin/admins/:id
```

| admin 字段 | D 字段 |
| --- | --- |
| `name` | `nickname`（C 端）/ `displayName`（后台账号） |
| `phone` | `phone`（operator 脱敏） |
| `role` 超级管理员 / 内容编辑 | D `role`：`super_admin` / `operator` |
| `status` 正常 / 禁用 | `active` / `disabled` |

后台页面目前没有登录框；D 的后台接口都要 `Authorization: Bearer <admin token>`。B 需要先接 `/api/auth/admin/login`，把 token 存起来。

### 4.3 数据分析

admin 现在读：

```js
DB.analysis = {
  heat: [{ name, value }],
  trend: [number],
  funnel: [{ name, value }]
}
```

D 的 `GET /api/admin/analytics/summary` 返回：

```json
{
  "modules": [{ "moduleLabel": "首页", "pv": 879 }],
  "trend": [{ "day": "2026-11-12", "pv": 150 }],
  "funnel": { "steps": [{ "label": "进入首页", "sessions": 879 }] }
}
```

适配方式：

```js
heat   = summary.modules.map(x => ({ name: x.moduleLabel, value: x.pv }))
trend  = summary.trend.map(x => x.pv)
funnel = summary.funnel.steps.map(x => ({ name: x.label, value: x.sessions }))
```

AI 解读：

```text
GET  /api/admin/analytics/insights/latest
POST /api/admin/analytics/interpret
```

`operator` 可看分析，但不能发起 AI 解读（403）；完整手机号导出同理。

## 6. 已知缺口

| 缺口 | 影响 | 归属 |
| --- | --- | --- |
| `/api/home`、`/api/bikes`、`/api/bikes/:id`、`/api/bikes/filters`、`/api/favorites`、`/api/bikes/:id/favorite` | 小程序首页 / 车型 / 收藏仍只能 mock | C |
| `/api/chat` | 智能客服仍只能 mock | C |
| 管理后台登录页 / fetch 封装 | 后台仍是 `DB` 演示数据 | B |
| 图片上传 | 后台 Banner / 车型图仍是本地预览 | B / C |
| 真实微信登录 / 手机号 | `WECHAT_MOCK=true` 时只做本地模拟 | A / D 真机联调 |

D 的登录、手机号、活动、报名、我的报名、埋点、用户管理、统计导出、分析接口已经可以直接联调；等 C 的车型 / 首页 / 客服接口和 B 的后台 fetch 接上后，再把 `USE_MOCK` 全局关掉。
