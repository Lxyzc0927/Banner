# 01 · 需求与范围

## 1. 背景与我的分工

课程项目以「XX 摩托销售管理系统」为底稿，4 人一组，目标是在两周内按企业研发流程完成一个可现场演示的系统。项目包含 C 端小程序、运营管理后台、AI 数据分析与智能客服。

我在组内负责：

1. **登录与手机号授权**：微信登录、手机号授权绑定、登录态校验。
2. **后台账号与至少两种角色**：超级管理员 / 运营管理员，账号增改、角色与权限。
3. **C 端用户查询与禁用**：分页、搜索、状态筛选、禁用 / 启用、报名记录查看。
4. **活动发布**：活动 CRUD、发布、下架、名额与时间窗管理。
5. **报名防重与名额校验**：同一用户同一活动只能有一条有效报名；名额满、未开始、已结束、已下架分别返回明确错误。
6. **报名统计与名单导出**：名额 / 报名 / 取消 / 报名率、每日报名、CSV 名单。
7. **模拟访问数据**：可复现的会话、模块访问、活动点击、报名成功 / 失败事件。
8. **模块热度、访问趋势、转化漏斗**：聚合接口与可视化。
9. **调用大模型生成分析解读**：固定 JSON Schema，失败自动规则兜底。

对应 PPT 中的验收点：

- 管理后台「活动管理」：活动发布与下架、报名人数统计、名单导出。
- 管理后台「用户管理」：角色 / 权限分配（至少两角色）、C 端用户查询与禁用。
- 管理后台「用户数据分析」：基于模拟数据出图，模块热度、访问趋势、转化漏斗。
- AI 数据分析占 10%：造模拟数据，完成用户访问行为分析并出图。

## 2. 范围边界

### 2.1 本模块交付

| 类别 | 交付 |
| --- | --- |
| 接口 | 登录、手机号、后台账号、C 端用户、活动、报名、统计、导出、分析、AI 解读 |
| 数据 | `schema.sql`、种子数据、30 天模拟行为数据、可复现的生成脚本 |
| 统计 | 核心指标、模块热度、趋势、漏斗、渠道，Markdown + CSV + JSON |
| AI | Prompt、JSON Schema、真实调用、无 Key 兜底、结果落库 |
| 测试 | 29 个接口级自动化用例，覆盖主要正常 / 异常路径 |
| 演示 | 后台控制台（登录 / 看板 / 活动 / 用户 / 账号） |
| 文档 | 需求、架构、数据模型、API、分析口径、Git 分支、测试、演示 |

### 2.2 明确不做（避免范围蔓延）

- 不做车型主数据、车型图集、Banner、资讯内容管理（组内其他同学负责）。
- 不做智能客服多轮对话（组内其他同学负责）。
- 不做正式后台前端；`server/public/admin/` 是自测 / 演示控制台，正式后台可按同一套 API 重写。该目录刻意放在 `server/` 下，避免占用 B 负责的顶层 `admin/`。
- 不做小程序完整页面；提供登录、手机号、活动、报名的对接示例，页面由前端同学实现。
- 不做支付、退款、优惠券、短信、订阅消息。
- 不做生产级风控、人机验证、审计合规；当前审计日志只覆盖关键后台操作。
- 不做跨设备用户身份合并；漏斗按 session 统计。

## 3. 用户故事与验收标准

### US-AUTH-01 微信登录

作为购车用户，我希望用微信一键登录，以便收藏、报名和查看我的记录。

- **AC1** 给定用户首次进入小程序，当 `wx.login` 拿到 code 并调用登录接口，则服务端用 code 换 openid，创建用户并返回 token、用户信息、`isNew=true`。
- **AC2** 给定同一 openid 再次登录，则返回同一用户，`isNew=false`，不重复创建。
- **AC3** 给定用户已被管理员禁用，当再次登录或携带旧 token 访问，则返回 `1008`，并提示联系管理员。
- **AC4** 给定 token 过期或伪造，当访问需登录接口，则返回 HTTP 401 / `code=401`。

### US-AUTH-02 手机号授权

作为购车用户，我希望授权手机号后完成报名，以便活动方联系我。

- **AC1** 给定用户点击「授权手机号」，当小程序拿到 `getPhoneNumber` 的 code 并提交，则服务端换取手机号并绑定到当前用户。
- **AC2** 给定手机号已绑定其他微信账号，则返回 `1011`，不覆盖原绑定。
- **AC3** 给定用户未授权手机号，当点击报名，则返回 `1010`，前端引导先授权，不能白屏。
- **AC4** 本地 mock 模式可用 `phone` 或 `code=mock:手机号` 完成授权，便于无 AppID 联调。

### US-ADMIN-01 后台账号与角色

作为超级管理员，我希望创建运营账号并分配角色，以便控制后台操作边界。

- **AC1** 系统至少有两种角色：`super_admin`、`operator`。
- **AC2** 超级管理员可创建、编辑、禁用后台账号、重置密码；运营管理员不能访问账号管理接口（HTTP 403）。
- **AC3** 不能禁用当前登录账号；不能把当前账号降级；不能移除最后一名启用的超级管理员（`1007`）。
- **AC4** 后台密码使用 scrypt 加盐哈希存储，接口不返回密码哈希。

### US-USER-01 C 端用户查询与禁用

作为运营，我希望搜索用户并禁用违规账号，以便控制报名质量。

- **AC1** 用户列表支持 `page/pageSize/keyword/status`，返回 `total/list`；关键词匹配昵称、手机号、openid。
- **AC2** 禁用必须填写原因；禁用后 token 立即失效，无法重新登录和报名。
- **AC3** 启用后用户可恢复登录；历史报名记录保留。
- **AC4** 用户详情可查看最近报名记录；用户报名列表支持分页。

### US-ACT-01 活动发布与下架

作为运营，我希望发布活动并随时下架，以便控制 C 端可见内容。

- **AC1** 活动字段包含标题、副标题、封面、详情、地点、活动时间、报名时间、名额、状态。
- **AC2** 新建默认草稿；草稿 C 端不可见；发布后 C 端列表 / 详情可见；下架后 C 端不可见、不可报名。
- **AC3** 活动结束时间必须晚于开始时间；报名截止必须晚于报名开始且不能晚于活动结束；名额必须大于 0。
- **AC4** 编辑使用 `version` 乐观锁；版本不一致返回 `1012`，避免两人同时改覆盖。
- **AC5** 名额不能改到小于当前已报名人数（`1009`）。

### US-ACT-02 报名防重与名额校验

作为购车用户，我希望报名一次就成功，避免重复提交和名额超卖。

- **AC1** 给定用户未报名且名额未满、在报名时间内、已授权手机号，当提交报名，则创建 `confirmed` 记录并返回报名编号。
- **AC2** 给定用户已报名，当再次提交，则返回 `1004`，并带上已有报名编号，不新增记录。
- **AC3** 给定名额已满，当提交，则返回 `1003`，不新增记录。
- **AC4** 给定报名未开始 / 已结束 / 活动已结束，当提交，则返回 `1002`；活动已下架返回 `1005`；未授权手机号返回 `1010`。
- **AC5** 给定多个请求并发抢最后一个名额，则只有 1 个成功，其余返回 `1003`。
- **AC6** 用户可取消报名（活动结束前），取消后释放名额；同一用户可重新报名，但同一时刻只能有一条有效报名。

### US-ACT-03 报名统计与名单导出

作为运营，我希望看到报名进度并导出名单，以便现场签到和复盘。

- **AC1** 统计接口返回名额、已报名、取消、剩余、报名率、取消率、近 14 天每日报名、最近报名。
- **AC2** 名单支持分页、状态筛选、关键词搜索（手机号 / 报名编号 / 昵称）。
- **AC3** 导出 CSV 带 UTF-8 BOM，Excel 打开中文不乱码；包含报名编号、活动名称、用户 ID、昵称、手机号、状态、报名时间、取消时间、备注。
- **AC4** 对以 `= + - @` 开头的内容做公式注入防护；导出动作写审计日志。
- **AC5** 运营管理员可导出；后台账号管理仍然只有超级管理员可用。

### US-AN-01 模拟访问数据

作为数据分析模块开发者，我需要可复现的模拟行为数据，以便在没有真实埋点时完成分析与演示。

- **AC1** 生成脚本支持 `--days/--sessions/--seed/--clear`；同一 seed 生成同一份数据。
- **AC2** 事件覆盖首页、车型、活动、我的、智能客服五个模块，字段包含 visitor、user、session、module、action、page、target、channel、duration、time。
- **AC3** 只有真正走到「报名成功」的会话才写报名表；名额、时间窗、重复报名、未授权手机号会被真实拦截。
- **AC4** 30 天、约 1800 个会话、约 6000 条事件、约 130 条报名；可一键重建。

### US-AN-02 模块热度、趋势、漏斗

作为运营，我希望看到模块热度、访问趋势和转化漏斗，以便判断流量与转化问题。

- **AC1** 模块热度返回 PV、UV、平均停留、PV 占比。
- **AC2** 趋势按天返回 PV、UV、会话、报名、报名/访客转化率；支持 7/14/30 天。
- **AC3** 漏斗返回 5 步：进入首页 → 浏览活动列表 → 查看活动详情 → 点击报名 → 报名成功；返回会话数、相对首步、相对上一步、流失率、最大流失环节。
- **AC4** 漏斗严格按同一 session 内时间顺序计算，后一步必须发生在前一步之后；跨会话不合并。
- **AC5** 所有接口支持 `from/to`，默认 14 天，最大 366 天。

### US-AN-03 大模型分析解读

作为运营负责人，我希望系统把统计结果翻译成可执行的解读，以便快速做决策。

- **AC1** 配置 `LLM_API_KEY` 时调用 OpenAI 兼容接口，要求返回固定 JSON：headline、summary、findings、recommendations、risks、confidence。
- **AC2** 未配置 Key、请求超时、返回非 JSON 或结构不合格时，自动使用规则兜底；结果 `source=fallback`，页面明确标注「规则兜底」。
- **AC3** 解读结果落库 `ai_insight`，保存区间、来源、模型、Prompt 版本、summary、输入快照。
- **AC4** 不把用户手机号、昵称等明细发给大模型，只发聚合指标。
- **AC5** 单管理员 3 秒内只能请求一次，避免误触造成费用。

## 4. 交付物与验收映射

| PPT 要求 | 本模块实现 | 验收方式 |
| --- | --- | --- |
| 登录 / 手机号授权 | `/api/auth/wechat/login`、`/api/auth/wechat/phone` | 后台「用户管理」或 curl；测试用例 |
| 后台账号、至少两角色 | `/api/admin/admins`、权限点 | 用 operator 访问账号管理返回 403 |
| C 端用户查询 / 禁用 | `/api/admin/users`、`PATCH status` | 后台用户页禁用后重新登录返回 1008 |
| 活动发布 / 下架 | `/api/admin/activities`、publish/offline | 后台活动页操作，C 端列表可见性变化 |
| 报名防重 / 名额 | `POST /api/activities/:id/signup` | 重复报名 1004，名额满 1003，并发测试 |
| 报名统计 / 名单导出 | `/stats`、`/signups`、`/export` | 后台统计弹窗 + 下载 CSV 用 Excel 打开 |
| 模拟访问数据 | `npm run mock` | 30 天数据，固定 seed 可复现 |
| 模块热度 / 趋势 / 漏斗 | `/api/admin/analytics/*` | 后台看板 + `reports/analytics_summary.md` |
| 大模型分析解读 | `/api/admin/analytics/interpret` | 配置 Key 显示「大模型生成」；无 Key 显示「规则兜底」 |

## 5. 非功能要求

- **一致性**：所有接口统一信封；错误码集中管理；分页统一 `page/pageSize/total/list`。
- **安全**：密码 scrypt；JWT HMAC；禁用即时生效；后台权限点校验；CSV 公式注入防护；不返回密码哈希；`.env` 不入库；默认只监听 `127.0.0.1`，监听局域网/公网前强制替换示例密钥与后台密码。
- **兼容**：后端同时提供 `/api/auth/wx-login`、`/api/auth/phone`、`/api/signups/mine` 三个别名，兼容小程序现有调用，避免 A 改页面才能联调。
- **可复现**：固定 seed 的模拟数据；一键建库 / 生成 / 报告脚本。
- **可测试**：接口级测试使用内存 SQLite，不依赖外部服务；29 个用例可在 1 秒内跑完。
- **可协作**：按领域分目录，路由自动发现；公共文件变更先和组长确认，在自己的分支提交后合并回 `main`。
- **可演示**：无外部 CDN、无前端构建步骤；断网也能打开后台（除字体外全部本地资源）。
